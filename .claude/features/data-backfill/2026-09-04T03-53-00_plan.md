## Architecture

### Summary
`fetch/backfill.py` is a thin orchestrator over T2's already-proven primitive. It enumerates the
D5 window into 1440 `(model, init_time, lead_h)` work items, runs them through
`ThreadPoolExecutor(8)` calling `fetch_point()` **unmodified**, classifies every outcome per D3 into
an append-only JSONL ledger, and then derives `data/forecasts.parquet` and `data/coverage.json` as a
**pure function of that ledger**. `fetch/obs.py` independently pulls IEM ASOS `OMA` into
`data/obs.parquet` with true off-hour timestamps. T4 does **not** join, score or blend.

Making the ledger the single source of truth buys three things at once: resumability (FR7), a
deterministic write path, and an offline-testable seam that satisfies SPEC §13 with **zero**
networked tests.

### Data Flow

```
                    fetch/window.py  (D5: end_init = latest synoptic <= now-30h,
                    [FOUNDATION]      120 inits back, leads 6/12/24 -> 1440 items;
                          |           obs bounds = [min(valid)-1h, max(valid)+1h])
            +-------------+--------------------+
            |                                  |
            v                                  v
   fetch/backfill.py                     fetch/obs.py
   ThreadPoolExecutor(8)                 IEM ASOS CSV (spike F4 URL)
   |  900 s deadline guard               |  drop tmpf == 'M' / unparseable
   |  3 attempts, 2s/5s, transient only  |  NEVER interpolate / resample / round
   v                                     |  dedupe exact valid_time, sort asc
   fetch.grib.fetch_point()  <-- UNMODIFIED except D3's additive ArchiveMissing
   |                                     |
   v  classify (D3)                      |
   data/raw/backfill_ledger.jsonl        |
   (append-only, one line per attempt,   |
    lock-guarded; resume reads it first) |
            |                            |
            |  pure function             |
            +--------+                   |
                     v                   v
        data/forecasts.parquet     data/obs.parquet     data/coverage.json
        model,init_time,lead_h,    valid_time,temp_f    window bounds + per-model
        valid_time,temp_f                               + per-(model,lead) coverage
                     \                   |                        /
                      +------------------+-----------------------+
                                         v
                                    T5 reads all three
                                    (T5 decides exclusion, not T4)
```

### The two integrity guards this ticket exists to hold

1. **Archive gaps are results, not errors.** A 404/403 is *recorded*, *counted into the
   denominator*, and does **not** abort the run (SPEC §11 R2). Only a genuine failure
   (network/decode) is an error, and it is counted separately.
2. **The T4 analogue of the empty-join fake (SPEC §10).** An empty parquet passes a schema check
   perfectly. **Assert non-trivial row counts before writing.** This is a pipeline assertion in the
   sense of SPEC §13 ("data guards are assertions in the pipeline"), not a nicety.

### Non-negotiable integrity note, stated up front
**If HRRR lands under 90%, that is a result to report, not a bug to fix.** Do not widen the window,
move the site, change the denominator, or drop a lead time to lift a coverage number. SPEC §10 and
SPEC §9 hard-stop #3 make that the one action that ends the demo's credibility. T4 **flags**;
**T5 decides exclusion** (SPEC §5). T4 must never drop a model.

**SPEC §11 R1 (Open-Meteo) is RETIRED and FORBIDDEN.** There is no fallback source. If the NOAA
archive is unreachable *for the entire window* (a model with zero successes, or all 1440 attempts
failed), that is a SPEC §9 hard stop: log it, mark the ticket BLOCKED, move on. Do not implement,
import, or reach for Open-Meteo under any circumstance.

## Key Decisions

- **D3's `ArchiveMissing` is task 1.1 because it is a genuine blocker, not a tidy-up.** A bare
  `RuntimeError` labelled "§9 hard stop" on a 404 would abort the backfill on exactly the HRRR holes
  SPEC §11 R2 predicts. Subclassing `RuntimeError` keeps it additive and keeps all 81 T2 tests green.
- **T2 is finalized, so `fetch/grib.py` is now T4's to modify** — but only additively, and the
  validated decode path stays byte-identical.
- **The ledger is the single source of truth.** Both parquets and the coverage report are pure
  functions of it, which is what makes the write path deterministic, resumable, and offline-testable
  from a synthetic ledger with no network anywhere in the suite.
- **A 900 s deadline guard, not just a hope.** FR8 becomes an enforced property; the worst case of a
  hung socket (120 s × 3 attempts per worker) is bounded.
- **The obs acceptance check is `nunique()` on the floored hour, not a row count.** ~900 true rows
  cover ~720 hours; a row-count check would pass on 900 rows inside a single day.
- **`write_parquet_checked` centralises the SPEC §10 anti-fake assert.** An empty parquet passes a
  schema check perfectly — the row-count assert is the only thing standing between us and a
  beautifully-typed file of nothing.
- **`--executor process` ships from the start** so the cfgrib-under-threads escape hatch is a flag,
  not an invention at 05:00.
- **Coverage below 90% is a result to report, not a bug to fix.** Stated here so no downstream agent
  is tempted to widen the window.

## Notes for Implementer

- **`_get` wraps `requests.RequestException` in a plain `RuntimeError`** (`fetch/grib.py:197-209`),
  so `except requests.RequestException` in `backfill.py` never fires. Classify off
  `exc.__cause__`. Do not "fix" `_get`.
- **`GRIB_shortName` is `2t`, not `t2m`** — SPEC §3 and the spike are both literally wrong here; T2
  hit it live. `decode_point` already asserts correctly. **Do not add a second copy of the check.**
- **The APTMP trap is not NBM-specific** — GFS f006 carries `APTMP:2 m above ground` too (msg 585).
  The anchored needle `":TMP:2 m above ground:"` already handles both.
- **NAM's `.idx` has sub-message entries sharing a start byte**, so message numbers stay strings and
  the range end is the next *strictly greater* offset. Already handled in `fetch/idx.py` — it
  matters at 1440 messages.
- **NBM's message index moves with lead** (187/192/195 at f006/f012/f024). The `.idx` is parsed every
  call. **Never cache a message number across leads.**
- **A naive datetime is UTC, never local** (`fetch/grib.py:_as_utc`, line 54). Follow that rule in
  `window.py` and `obs.py`.
- **`pandas.Categorical` for `model` round-trips as a pyarrow dictionary type** and will surprise T5.
  Keep it `pa.string()`.
- Guards raise `AssertionError` with the SPEC clause in the message — match
  `fetch/grib.py:149-186`'s house style.
- Fixture provenance goes in `tests/fixtures/README.md` (7 fields, T2's format).
- Expect **~372 MB** of transient GRIB traffic across 1440 fetches (spike F2 extrapolation). Nothing
  is retained on disk beyond the ledger.
- If the smoke run shows sustained 503/429, drop to 4 workers and log it — 4 workers is still ~8 min,
  comfortably inside the guard.
