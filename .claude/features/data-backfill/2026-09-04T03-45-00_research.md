## Decisions (no open questions — user asleep, §9/§16 say do not ask)

### D1 — Concurrency: `ThreadPoolExecutor(max_workers=8)`
Spike F2 measured ~0.8 s/fetch serial, ~372 MB total, ~1 min at 8x. 8 is the validated number and
is polite to a public NOAA bucket. Do not raise it: decode is CPU-bound under the GIL, so >8 buys
little, and the 15-minute budget is a **constraint, not a target** — there is ~10x headroom at 8x.

### D2 — Retry / backoff / timeout
- `fetch.grib._get` already retries once on a socket exception with `timeout=120`. Leave it alone.
- T4 adds a **task-level** retry: up to 2 retries (3 attempts total) with backoff 2 s then 5 s,
  **for transient classes only** — network exception, non-GRIB body, decode error.
- **404/403 is never retried.** A key that does not exist will not exist 5 seconds later.
- **Global deadline guard, default 900 s.** On expiry, stop submitting, mark unsubmitted work
  `not_attempted`, write what exists, and report. This makes "under 15 minutes" an enforced
  property rather than a hope, and bounds the worst case of a hung socket (120 s x 3 attempts
  holds one of 8 workers).

### D3 — Missing vs failed: exact classification
| Outcome | Trigger | Counted as | Retried |
|---|---|---|---|
| `success` | `fetch_point` returns a dict | numerator of coverage | — |
| `missing` | HTTP **404 or 403** (or S3 `NoSuchKey`) on the `.idx` **or** the ranged GRIB GET | denominator only; **expected**, never aborts (SPEC §11 R2) | no |
| `failed_network` | `requests.RequestException` after `_get`'s own retry | denominator only; logged with the exception | yes (2) |
| `failed_decode` | non-GRIB body, `ValueError` from `select_tmp_2m` (needle absent), `AssertionError` from `decode_point` (aptmp / t2m / distance guards) | denominator only; logged with the message | yes (2) |
| `not_attempted` | deadline guard fired | denominator only; reported explicitly | no |

**Blocker to resolve first:** `fetch_point` today raises a bare `RuntimeError` whose message says
`"SPEC §9 hard stop"` for *any* non-200 `.idx` status, **including 404** (`fetch/grib.py:224-228`,
`:236-240`). That conflates an expected archive hole with a hard stop. Fix: a minimal **additive**
change to `fetch/grib.py` — `class ArchiveMissing(RuntimeError)` raised when the status is 404/403,
message reworded to cite §11 R2 rather than §9. Subclassing `RuntimeError` keeps every existing
caller and all 81 T2 tests green (no test asserts on 404 — verified by grep). Sequence this after
T2's `/finalize` commit lands, as T4's first task. Fallback if `fetch/grib.py` is locked:
string-match the status out of the message — fragile, second choice only.

**Whole-run hard stop (SPEC §9.1 only):** if a model has **zero** successes across the entire
window, or every one of the 1440 attempts failed. HRRR merely having holes is *not* a hard stop.

### D4 — Coverage denominator (must match T5)
- Per model: **360** = 30 days x 4 inits x 3 leads. Coverage % = `success / 360 * 100`.
- Per (model, lead_h): **120**. Reported too, because T5's paired comparison is per lead time.
- Flag threshold: `< 90.0` (a model at exactly 90.0% passes). T4 **flags and reports**;
  **T5 decides the exclusion** (SPEC §5). T4 must not drop a model.

### D5 — Window definition (TR4)
`end_init` = the latest synoptic (00/06/12/18z) init at or before `now_utc - 30 h`. The 30-hour
setback guarantees the 24 h lead has verified and cleared archive latency. Inits are the 120 slots
running back from `end_init` inclusive → exactly 360 (init, lead) pairs per model. The obs request
window is `[min(valid_time) - 1 h, max(valid_time) + 1 h]`. **Both bounds are written into
`data/coverage.json`** so T5 reads them rather than recomputing.

### D6 — Observations: exactly what T4 stores
Spike F4 URL, `tz=Etc/UTC&format=onlycomma`, `data=tmpf`. Of ~9242 rows, ~899 are non-`M`
(ASOS reports every 5 min; only routine/special obs carry `tmpf`), covering **720/720 distinct
hours with no gaps**. T4 therefore stores **~900 rows, not 720** — the true off-hour timestamps
(`:53`, `:05`, `:17`…) at full minute resolution, parsed `utc=True`. Dedupe on exact duplicate
`valid_time` (keep first) so T5's nearest join is deterministic; sort ascending. **No rounding, no
resampling, no interpolation.** The acceptance floor's "obs cover ~720 hours" is a check on
`nunique()` of the floored hour, **not** on row count — assert `>= 700`.

### D7 — Resumability: an append-only ledger, no raw byte cache
Write `data/raw/backfill_ledger.jsonl` — one JSON line per attempt (`model, init_time, lead_h,
valid_time, status, temp_f, grid_lat, grid_lon, distance_deg, error, attempted_at`), appended under
a lock. On start, load it and skip any (model, init, lead) already `success` or `missing`; retry
`failed_*` / `not_attempted`. **Both parquet files and the coverage report are then written as a
pure function of the ledger**, which makes the write path deterministic and unit-testable offline
from a synthetic ledger.
Do **not** cache the 372 MB of raw GRIB bytes: the expensive thing to preserve is the *outcome*
(~200 KB), and a warm-ledger rerun costs seconds. `data/raw/` already holds T2's 4 probe `.bin`
files — put T4's artifacts under `data/raw/` with a `backfill_` prefix so nothing collides.

### D8 — Testing split (SPEC §13)
**Offline pytest (all of it):** coverage arithmetic incl. the 90.0 boundary; the D3 status
classification given synthetic exceptions; the ledger→parquet writer's exact schema, column order,
dtypes and tz-awareness on round-trip; IEM CSV parsing against a small captured fixture (drops `M`,
no interpolation, dedupe, sort, distinct-hour count); the D5 window enumeration (120 inits, 360
pairs, all tz-aware UTC); ledger resume skips.
**Manual/CLI only:** the live run itself, plus a `--models hrrr --days 1` smoke mode (24 fetches,
~30 s) run before the full backfill.
The IEM fixture needs one live call — capture it with a dev-only script following T2's
`fetch/capture_fixtures.py` pattern (run by hand, never by pytest, imports nothing under test),
and record provenance in `tests/fixtures/README.md`.

4. NBM's message index moves with lead (187/192/195) — the `.idx` is parsed every call. Never cache

## Patterns to Follow
- **Pure per-call, no module-level session or global state** — `fetch/grib.py`'s stated invariant.
  `fetch/backfill.py` owns the pool; the fetch primitive stays stateless.
- **Guards raise `AssertionError` with the SPEC clause in the message** (`fetch/grib.py:149-186`).
  T4's non-trivial-output asserts should read the same way.
- **Dev-only capture script that imports nothing under test** — T2's independent-witness pattern.
- **Fixture provenance recorded in `tests/fixtures/README.md`.**
- **`_as_utc()`**: a naive datetime is UTC, never local (`fetch/grib.py:54`).
- **Path-scoped commits** while a concurrent ticket is live (T2 did this against T3).

## Patterns to Avoid
- Reimplementing any part of the fetch/decode path. T2 is GREEN; wrap it.
- Hardcoding a GRIB message index or reusing one across leads.
- `GRIB_shortName == "t2m"` (it is `2t`).
- Resampling/rounding/interpolating observations, or joining on the exact hour (F5/F11).
- Treating a 404 as fatal, or letting one bad run abort 1440 fetches.
- Naive timestamps, or `pandas.Categorical` for `model` (round-trips as pyarrow dictionary type).
- **The T4 analogue of the empty-join fake:** an empty parquet passes a schema check perfectly.
  Assert `len(forecasts) > 0`, per-model successes > 0, and obs distinct hours ≥ 700 before writing.
- Touching `backend/`, `frontend/`, or `data/results.json` — T3 owns them right now.

## Recommended Approach

Build `fetch/backfill.py` as a thin orchestrator over T2's proven primitive: enumerate the D5
window into 1440 work items, run them through `ThreadPoolExecutor(8)` calling `fetch_point`
unmodified, classify each outcome per D3 into an append-only JSONL ledger, then derive
`forecasts.parquet`, `obs.parquet` and `data/coverage.json` from the ledger under an explicit
pyarrow schema. Making the ledger the single source of truth buys resumability, a deterministic
write path, and an offline-testable seam that satisfies SPEC §13 without any networked test.
Sequence: (1) the additive `ArchiveMissing` fix, (2) `fetch/obs.py` + its fixture (fast, unblocks
T5's obs side early), (3) the 24-fetch smoke run to validate threading and rate, (4) the full run.
