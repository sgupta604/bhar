## Goal

Build the single-fetch primitive: given (model, init_time, lead_h), parse the NOAA `.idx`, HTTP
range-fetch the anchored `:TMP:2 m above ground:` message, decode it with cfgrib, take the nearest
grid cell to KOMA (41.3032, -95.8941), and return degrees F. The 30-day parallel backfill is **T4,
not T2**.

### NEW finding, not in the spike — NAM's `.idx` has sub-message entries

NAM's f006 index has 454 lines but message numbers are **not all integers** and **consecutive
entries can share a start byte**:

```
284.1:42835573:d=2026080512:UGRD:975 mb:6 hour fcst:
284.2:42835573:d=2026080512:VGRD:975 mb:6 hour fcst:
```

Two consequences the parser must handle (both cheap, both silent failures if missed):
1. `int(fields[0])` **raises on NAM**. Keep the message number as a **string**; never derive it
   from `enumerate()` (line 361 of NAM's idx is message 321).
2. The byte-range end must be **the next entry with a strictly greater start offset**, not
   literally the next line — otherwise a `.1`/`.2` pair yields a zero/negative-length range.
3. If no later offset exists (last message in the file), issue an **open-ended
   `Range: bytes={start}-`**.

The 2 m TMP message itself is unaffected today (NAM 321 → 48465225, next 322 → 48706129, 235 KB,
matching spike F2), but T4 fetches 1440 messages across four leads and models; the robust rule
costs three lines.

## Code Examples from Spec

hits = [ln for ln in lines if NEEDLE in ln and "ens std dev" not in ln]

Note the leading colon is what excludes `APTMP:2 m above ground`.

## Patterns to Follow

- **`tests/fixtures/README.md` provenance discipline** — seven fields per capture: date, model, init
  hour, lead, source URL, byte range, expected value. "A capture with no provenance entry is not a
  fixture, it is an unexplained blob."
- **`tests/conftest.py`** — path fixtures derived from `Path(__file__)`, never from cwd. Reuse
  `REPO_ROOT` / `FIXTURES` rather than re-rolling paths.
- **`tests/test_scaffold.py`** — assertion messages that name the SPEC clause and print the actual
  value. Follow that style; a failing GRIB test at 04:00 must be diagnosable without a debugger.
- **T1's `run.sh` port-squatter handling** — it refused to report green on a fake success. Same
  instinct here: assert the `GRIB` magic, assert `t2m`, assert exactly one index hit.
- `--strict-markers` is on; `integration` is the only declared marker.

## Patterns to Avoid

- **The unanchored needle `"TMP:2 m above ground"`.** It silently returns apparent temperature.
- **Any hardcoded message index.** NBM's moves 187/192/195.
- `enumerate()`-derived or `int()`-parsed message numbers (NAM has `284.1`).
- Live network inside pytest (SPEC §13).
- A `.gitkeep` in `data/raw/` as a substitute for `mkdir -p`.
- Interpolation of any kind — nearest cell only.
- Retrying into the Open-Meteo fallback (SPEC §11 R1, RETIRED/FORBIDDEN).
- Building T4's parallel backfill here.

## Decisions (recorded, not asked — user is asleep)

- **D1 — Live probe is T2's first task, as a capture script, not a test.**
  `uv run python -m fetch.capture_fixtures` fetches one real message for each model, prints the
  decoded value, and writes fixtures + provenance. This satisfies the plan-agent's
  verification-first rule and produces the offline test corpus in the same pass. If it prints
  68.24 / 71.65 / 69.53 / 70.61, the primitive is proven before a single test is written.
- **D2 — Resolution of the §13 (no live test) vs §8 (integration fixture) tension:** capture once,
  test offline forever. The live check is a **manual probe** (the script above), re-runnable by
  hand; it is never invoked by pytest. Fixtures to capture, all from **2026-08-05 12z**:
  - `tests/fixtures/idx/{hrrr,gfs,nam,nbm}_20260805_12z_f006.idx` — full `.idx` text, verbatim.
  - `tests/fixtures/idx/nbm_20260805_12z_{f012,f024}.idx` — proves the index moves (192 / 195).
  - `tests/fixtures/grib/{hrrr,gfs,nam,nbm}_20260805_12z_f006_t2m.bin` — the exact range-request
    bytes for the 2 m TMP message.
  - One provenance entry per file appended to `tests/fixtures/README.md` with all seven required
    fields (date, model, init hour, lead, source URL, byte range, expected value).
- **D3 — Fixture naming vs `.gitignore`:** captured GRIB bytes use the **`.bin`** extension, since
  `.gitignore:24` is `*.grib2` and would silently swallow a `.grib2` name. Belt and braces: the
  capture script runs `git check-ignore -q <file>` on each output and **fails loudly** if any
  fixture is ignored. (An orchestrator-side `!tests/fixtures/**` negation in `.gitignore` is the
  alternative and is permitted, but is not required if `.bin` is used.)
- **D4 — `data/raw/`:** `Path("data/raw").mkdir(parents=True, exist_ok=True)` at the point of use.
  Never assume `.gitkeep` survives a clone — verified that it does not.
- **D5 — Byte-range end rule:** next entry with a **strictly greater** start offset, minus 1;
  open-ended `bytes={start}-` when none exists.
- **D6 — Message numbers are strings.** NAM emits `284.1` / `284.2`.
- **D7 — Distance metric:** plain euclidean degrees, to reproduce spike F11's printed distances
  exactly. Assert the chosen cell is within 0.5 deg of KOMA.
- **D8 — Longitudes normalized to [-180, 180]** before the distance computation (GFS is 0–360).
- **D9 — Tolerance:** `abs(actual - expected) < 0.01` on the four acceptance values.
- **D10 — T4 interface, locked now:** `fetch_point(model: str, init_time: datetime, lead_h: int)
  -> dict` returning `model, init_time, lead_h, valid_time, temp_f, grid_lat, grid_lon,
  distance_deg`. Pure per-call, no shared state, no retries beyond one — so T4 can wrap it in a
  thread pool without touching it.

## Recommended Approach

Two small modules plus a capture script. `fetch/idx.py` is pure text handling — `.idx` bytes in,
one selected record and a byte range out — which makes the highest-risk logic (the anchored needle,
the `ens std dev` rejection, NAM's sub-messages, the moving NBM index) unit-testable offline against
captured text with zero network. `fetch/grib.py` does the S3 key building, the range request, the
cfgrib decode, the nearest-cell pick and the K→F conversion, and its risky half (decode → value)
is tested offline against captured message bytes. Order: live probe/capture first (D1), then
tests against what was captured, then the code that satisfies them. That order is what turns
"proven in a spike" into "proven in CI at 04:00 with the network down".
