## Architecture

### Summary
Two small pure-ish modules plus one dev-only capture script. `fetch/idx.py` is text in → one
selected record and a byte range out (the highest-risk logic: anchored needle, `ens std dev`
rejection, NAM sub-messages, the moving NBM index) — 100% unit-testable offline. `fetch/grib.py`
builds the S3 key, issues the range request, decodes with cfgrib, picks the nearest grid cell to
KOMA and converts K→F, exposing the single T4 primitive `fetch_point()`. `fetch/capture_fixtures.py`
performs the one-and-only live probe and writes the offline test corpus in the same pass.

### Data Flow
```
                       ┌──────────────────────── T2 SCOPE ────────────────────────┐
(model, init, lead) ─> │ build_urls ─> GET {key}.idx ─> parse_idx ─> select_tmp_2m │
                       │                                     │                    │
                       │                               byte_range                 │
                       │                                     v                    │
                       │        GET {key}  Range: bytes=S-E  ─> GRIB msg bytes     │
                       │                                     v                    │
                       │        cfgrib decode (assert t2m) ─> nearest cell ─> K→F  │
                       └──────────────────────────┬───────────────────────────────┘
                                                  v
                                        dict{model, init_time, lead_h,
                                             valid_time, temp_f,
                                             grid_lat, grid_lon, distance_deg}

                                      (T4 wraps this in a thread pool — NOT T2)

   (self-contained; imports neither module)         tests/fixtures/grib/*.bin

```

## Key Decisions
- **The capture script is self-contained and imports neither module.** An independent witness: if
  probe and implementation shared code, a shared bug would prove itself correct. Cost is ~30
  duplicated lines; the payoff is that the acceptance floor is an actual check.
- **Streams 2 and 3 run in parallel against signatures locked in this document**, rather than 3
  waiting on 2. This is the contract-first rule applied inside a single ticket; it is what makes an
  M-scope ticket fit the remaining time.
- **Fixtures are `.bin`, not `.grib2`** — `.gitignore:24` would silently swallow the latter, and the
  failure mode (green locally, gone on a clean clone) is invisible until the worst moment. Belt and
  braces: the capture script hard-fails on `git check-ignore`. Chosen over editing `.gitignore`
  because the tree is shared with a concurrent ticket.
- **Message numbers are strings; byte-range end is the next strictly-greater offset; last message
  gets an open-ended range.** NAM emits `284.1`/`284.2` sharing a start byte. Costs three lines,
  prevents a zero-length range on 1 of 1440 T4 fetches.
- **`abs(diff) < 0.01`, never widened.** Recorded here so that "just loosen it" is visibly a SPEC
  §10 violation and not a judgement call at 05:00.
- **`fetch_point` is pure per-call** so T4 can thread-pool it without modification — the interface
  is locked now, before T4 exists, precisely so T4 never has to renegotiate it.
- **Plain euclidean degrees for distance** — reproduces spike F11's printed distances exactly; a
  cos(lat)-weighted metric picks the same cell, so the choice is not load-bearing.

## Notes for Implementer
- The leading colon in `":TMP:2 m above ground:"` is the whole ballgame. `APTMP:2 m above ground` is
  **message 1** in NBM; the unanchored needle silently returns apparent temperature. This bug was hit
  for real during the spike.
- GFS longitudes are 0–360; normalize with `((lon + 180) % 360) - 180` before any distance math.
  If you skip it, the 71.65 assertion catches you immediately.
- GFS decodes to 1-D lat/lon; HRRR/NAM/NBM to 2-D curvilinear. Broadcast 1-D to a mesh, then
  `argmin` over the flattened distance array — one helper handles both.
- `backend_kwargs={"indexpath": ""}` is not optional. A stale cfgrib sidecar in `tests/fixtures/` is
  a classic false-result source and would get committed.
- `data/raw/.gitkeep` is gitignored and will not exist in a fresh clone — `mkdir(parents=True,
  exist_ok=True)` at the point of use, always.
- Failure messages should name the SPEC clause and print the actual value. A failing GRIB test at
  04:00 must be diagnosable from the pytest output alone.
- If the NOAA archive is down during Task 1.1: that is a §9 hard stop. Log it, mark T2 **BLOCKED**,
  move to the next non-dependent ticket. Do **not** reach for Open-Meteo.
