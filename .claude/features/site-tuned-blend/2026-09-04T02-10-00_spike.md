## F3. Open-Meteo is a FALLBACK ONLY, and has two traps

- **Previous Runs API** (`https://previous-runs-api.open-meteo.com/v1/forecast`) offers only
  **fixed 24-hour lead multiples** — `temperature_2m_previous_day1..7`. **There is no 6h or 12h
  lead.** Using it means losing two of the three lead times.
- HRRR and NAM populate only `_previous_day1`; day2–7 are null across all 744 hours. GFS and NBM
  populate day1–7.
- **TRAP:** `models=gfs_seamless` returns values **byte-identical to `ncep_hrrr_conus`** (HRRR is
  its short-range component). Using both would put the same model in the blend twice under two
  names. Use `gfs_global` or `ncep_gfs013` for a distinct GFS.
- **LICENSE:** free tier is **non-commercial only**. Acceptable for an internal demo; must not
  ship commercially.

## F5. BRIEF §10 Q8 IS WRONG — METAR is NOT on the hour

The BRIEF assumes "METAR valid times are on the hour." They are not. Observed rows:

```
station,valid,tmpf
OMA,2026-08-05 00:05,M
OMA,2026-08-05 00:30,64.00
```

ASOS reports at 5-minute intervals; the routine hourly observation lands near `:53` or `:05`.
**An exact-timestamp join to model valid times matches ZERO rows** and produces an empty
dataframe that scores perfectly. This is the single most likely way this project silently
produces a fake result.

**Required rule:** nearest valid (non-`M`) observation within +/-30 minutes of the target hour,
with the actual time offset recorded as a column on every matched row, and a hard assertion on
matched row count.

## F9. TRAP — `"TMP:2 m above ground"` matches the WRONG variable. Anchor the needle.

The obvious search string is a **substring of `APTMP:2 m above ground`** (apparent temperature).
In NBM's index that is **message 1**, so a naive match silently returns apparent temperature and
labels it 2 m temperature. This was hit for real during validation:

```
1:0:d=2026080512:APTMP:2 m above ground:6 hour fcst:          <- naive match lands HERE
187:153756600:d=2026080512:TMP:2 m above ground:6 hour fcst:  <- the one we want
188:155939231:d=2026080512:TMP:2 m above ground:6 hour fcst:ens std dev   <- also matches
```

**Required:** match the anchored needle **`":TMP:2 m above ground:"`** (leading colon), and
**reject any line containing `ens std dev`**. Assert the decoded variable short name is `t2m`
and NOT `aptmp` — that assertion is cheap and catches this whole class of error.
**Write a unit test for this against a captured NBM `.idx` fixture.**
