## Fetch / render flow (concrete)

```
1  inline <head> script  → html[data-theme=light|dark]      (before any stylesheet paints)
2  API_BASE = ?api= || http://localhost:8000
3  fetch(API_BASE + '/api/forecast')
4  !r.ok → r.text() → JSON.parse → j.detail → throw {userDetail, status}
                                   (raw body if unparseable — app.js:31-37 pattern)
5  ok    → r.json() → boot(payload)
6  boot: applySynthetic(meta)      // sets data-synthetic + [SYNTHETIC] title + banner text
        applyStale(meta.cycle)     // sets data-stale, fills pill + reason
        renderHeader(meta)         // title, site line, scope line
        renderHeadline(rows[0], meta.cycle)   // stat card + run label
        buildGrid(meta, forecast, gaps)       // merge into one n_steps-long array by valid_time
        renderStrip(grid, meta)               // cols, rows, bands, boundary, cells, marks
        renderStripNote(meta, gaps)           // iff horizon_h < 48
        renderSkillPlaceholder(skill, meta)   // card + #skill-beyond-fitted
        selectCell(0)                         // panel is never empty on first paint
7  catch → renderEmptyState(userDetail)  // hide shell, render .card.empty-state, run label
                                          // above it iff a cycle is knowable, else omitted
```

**Grid merge (the load-bearing step).** Build `n_steps = horizon_h / step_h` slots keyed by
`valid_time` (equivalently `lead_h = step_h * i`). Fill from `forecast[]`, then from `gaps[]`.
**Assert the union covers every slot exactly once** — §9 rule 8 guarantees it, and an assertion here
is the frontend twin of the project's "assert on join match counts" rule. A silently short strip is
the fake-green failure in a new costume.

**Column count.** `cols = clamp(4, floor((available + 8) / (108 + 8)), 8)`; where more than one count
sits inside the clamp, prefer the one that puts the boundary on a row edge. Below the 4-col floor,
set `data-overflow="scroll"` on the container.

**Boundary form selection.** `firstExtrapIdx = grid.findIndex(r => r.is_extrapolated_lead)`. If
`firstExtrapIdx % cols === 0` → form 1 (`.strip-boundary` between rows). Else → form 2
(`data-boundary-start="true"` on that cell and its band). At 1440×900 with the current payload
(`firstExtrapIdx = 8`, `cols = 8`) it is **form 1** — but **both forms must ship**, because the
column count is computed and a narrower window flips it.

## State-gating scheme

| `<html>` attribute | Source | Set when | Absent when | CSS |
|---|---|---|---|---|
| `data-synthetic="true"` | `meta.is_synthetic` (boolean) | `true` | `false` — attribute never written | `tokens.css:19-47` (linked, verbatim) |
| `data-stale="true"` | `meta.cycle.is_stale` (boolean) | `true` | `false` — attribute never written | `forecast.css` (§3's literal block) |
| `data-theme="light"\|"dark"` | `localStorage['internal-portal:theme']` | always (two values) | never | `tokens.css:236-281` (linked, already shipped) |

Payload facts are `"true"`-or-absent; the viewer preference carries an explicit value because a
theme has no "off". **JS never writes `"false"` into a state attribute** and never touches
`style.display` for state.

## The hostile fixture — what it actually exercises

`data/forecast.fixture.json` (`is_synthetic: true`), against the live `data/forecast.json`:

| | fixture | live (`forecast.json`) |
|---|---|---|
| `forecast` rows / `gaps` | **14 / 2** | 16 / 0 |
| gap leads | **21** (mid-strip, inside the fitted range) and **48** (last cell) | — |
| extrapolated rows | **7** (27…45; 48 is a gap) | 8 (27…48) |
| `is_stale` | **true**, `cycles_fallen_back: 1`, `age_minutes: 82.9` | false, 0, 394 |
| `stale_reason` | non-null, long, must render verbatim and wrap | `null` |
| **zero-weight model** | **NAM** (`GFS: 0.1, NAM: 0.0`) | **GFS** (`GFS: 0.0, NAM: 0.1`) |
| `best_single_model` by lead | **HRRR / NBM / GFS** — varies | HRRR / HRRR / HRRR |
| `improvement_pct` @24 h | **−12.5** (blend LOST: mae 9.99 vs best single 8.88) | +16.5075 |
| `member_spread_f` | up to ~32 °F (absurd on purpose) | ~1–3 °F |

Three consequences for F5, all directly testable:

1. **The zero-weight model differs between the two payloads.** Any `GFS`-in-a-selector shortcut
   renders correctly on the live file and lies on the fixture. This is the cheapest possible proof
   that §1.4's "computed, never hardcoded" rule is honoured — render both and compare.
2. **`best_single_model` varies by lead in the fixture.** A hardcoded `HRRR` in the skill placeholder
   survives the live payload and fails the fixture.
3. **`age_minutes` is a float (`82.9`) in the fixture and an int (`394`) live.** `floor(v/60)` is
   correct for both; `parseInt`-style assumptions are not. The run label must read `1 h old`.

**How to load the fixture in a browser (no new code path).** `/api/forecast` reads
`data/forecast.json` and re-validates **per request**, so swapping the file is picked up with no
restart (F4 verified this live). Both files are gitignored. So:
`cp data/forecast.json /tmp/fc.live.json && cp data/forecast.fixture.json data/forecast.json`
→ screenshot → restore. **Do not add a `?src=`/`?fixture=` override to `forecast.js`** — that ships
a code path whose only purpose is to load fabricated data, which is the §11 failure with a query
parameter on it.
**503 state:** `mv data/forecast.json /tmp/` → the endpoint returns 503 with
`MISSING_FORECAST_DETAIL` (`backend/forecast_api.py:60-63`). A contract-failure 503 (a different
`detail`, carrying the offending JSON path) is produced by corrupting a value.

## Patterns to Follow

- **`app.js:56-64` — synthetic wiring, verbatim shape.** `if (!meta.is_synthetic) return;` guards on
  the boolean; then `setAttribute` + `document.title` prefix + banner `textContent`. Three effects,
  one boolean, zero `display` writes.
- **`app.js:29-43` — the error path.** Non-ok → read the body as text → try `JSON.parse` → prefer
  `j.detail` → fall back to the raw body. This is what surfaces FastAPI's `{"detail": …}` and still
  survives a non-JSON error page.
- **`app.js:487-509` — `renderEmptyState`.** Hide the shell via a class, build icon/title/body/detail
  into a dedicated `#error-slot`, and put the server's message in `.empty-detail` **verbatim**.
- **`index.html:8-20` — the pre-hydration snippet.** try/catch, `=== 'dark' ? 'dark' : 'light'`,
  inline, above the stylesheets. Mirror its shape exactly.
- **`format.js:19-28` — signed formatting.** Formats, then inspects the string's leading character
  and swaps in U+2212. Never `Math.abs`. Its comment block names the rule and the reason; keep that
  discipline in `forecast.js`.
- **`tokens.css:19-47` — the attribute-gated state block.** Rule off by default, one
  `html[data-x="true"]` selector turns it on. §3's stale block is this shape in `--warn`.
- **`models.js:17-21`** reads model colours out of `getComputedStyle` — see *Patterns to Avoid*.
- **`backend/forecast_api.py` docstring** — the house style for stating *what is deliberately absent
  and why*. `forecast.js` should carry the same for the members axis and the gap treatment.

## Patterns to Avoid

- **Resolving model colours to hex in JS.** `models.js` memoizes them and `app.js:508-524` documents
  the resulting bug: a theme flip repaints the background and leaves every mark on the old palette,
  requiring an explicit `resetColors()` + full re-render. `forecast.js` avoids the whole class by
  setting `--mark-color: var(--model-hrrr)` as a *reference*, so the cascade re-resolves for free.
- **`<link rel="stylesheet" href="app.css">`.** The one-line "fix" an implementer will reach for when
  retyping `.card`. It couples the forecast page to the demo path. Re-author instead (§7).
- **`<script src="theme.js">`.** Same coupling, in JS. See Q1.
- **Hardcoding `16` cells, `GFS` as the zero-weight model, `HRRR` as best single, or
  `"Omaha Eppley Airfield"`.** All four are data today and none is data tomorrow; the fixture
  falsifies two of them right now.
- **A hover tooltip for cell detail.** Unreachable by keyboard and by touch, and absent from the
  screenshot the demo needs (§1.2).
- **Recomputing staleness, banding, or `blend_f` on the client.** All three are payload fields,
  contract-validated server-side. A client recomputation is a second source of truth that can
  disagree with the pixels.
- **Writing `data-stale="false"`.** `[data-stale="true"]` does not match it; the state becomes
  invisible for the wrong reason and no selector can be written against it (§3).
- **`prefers-color-scheme`, split or whole.** The handoff checklist greps for it. `theme.js:47-52`
  splits the literal in two to pass that guard — and the `demo-overview` retrospective records that
  exact split as a guard that has gone stale. Do not import the trick.
- **Any `±` in `forecast.{html,js,css}`, including in a comment quoting T3 §3 or SPEC §6.2.**

## Recommended Approach

Build the three files bottom-up from tokens outward: `forecast.css` first (re-authored components
per TR3, then §2's strip block and §3's stale block **pasted verbatim** — they are specification
text, not sketches), then `forecast.html` as a static skeleton with every state's markup
unconditionally present, then `forecast.js` as a single-pass renderer with no framework and no
imports. Drive **all** state through `<html>` attributes so a browser devtools `setAttribute` can
demonstrate any state without a payload. Keep model colours as `var()` references end-to-end (TR8)
so dark mode costs one inline script and one existing `<link>`. Validate against **both** payloads
from day one — the fixture's gaps, its `−12.5 %` loss, and its NAM-zero-weight are the branches the
live 64/64-clean run cannot reach, and every one of them is a place where a plausible shortcut
renders a confident lie.

## Scope: L

Three new files, roughly 220 lines of HTML, 450 of CSS (≈300 of it verbatim from §2 and §3, ≈120
re-authored components) and 400 of JS. The volume is moderate; the size comes from breadth of
correctness surface — 18 FRs, ten discrete visual states, two boundary geometries, a dual-payload
verification matrix, and a compliance gate that has to be proven capable of failing. No new
dependency, no build step, no backend change, and no unresolved blocker.
