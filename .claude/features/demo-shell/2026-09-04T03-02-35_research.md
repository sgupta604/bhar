## Contract facts that drive the design

From SPEC §7 (verbatim rules) plus two derived facts the frontend depends on:

| Fact | Consequence |
|---|---|
| `results` keys are **strings** (`"6"`), `lead_times` is an array of **ints** (`6`) | Frontend must `String(lead)` to index. Cheap trap; call it out in the plan. |
| `blends` sorted by `mae_out_of_sample` ascending, includes **every** pure model | Leaderboard reads the head of the array; pure models always present for the chart endpoints. |
| `improvement_pct_vs_best_single` **may be zero or negative** | FR10. Never `Math.abs`, never clamp. |
| Grid step 0.1 over 4 models (SPEC §15 D7) | **286** weight vectors (`C(13,3)`), all of them enumerable. |

**Derived requirement, not in §7 but required by FR8 — flag to T5:** `blends` must contain the
**complete** 286-point grid, not a truncated top-N. The slider works by *exact lookup* into that
array (see D3). A truncated array silently breaks the slider when T5 lands. Encode this in `validate_results()`
as `len(blends) == 286` for a 4-model run (`comb(n_models*10 ... )` — compute from `models_included`),
so T5 fails loudly rather than shipping a dead slider.

## Decisions (no open questions — user is asleep)

### D1 — The `/design` pass: a written visual target, not a canvas
SPEC §12 requires a design pass "before T3 builds the frontend". It is 03:02, deadline 07:30, four
tickets remain, and the user is asleep and cannot refine a canvas. **Decision: the design pass output is
`.claude/features/demo-shell/design-target.md`** — a written visual target enumerating, per region:
exact Clarity token values, type sizes/faces, spacing steps, and *literal CSS blocks for the two things
Clarity does not define* (slider, chart/axis). This is genuinely a design pass: it fixes the visual target
before code exists, which is what §12 asks for. A canvas artifact would cost 20–40 minutes and return a
picture nobody awake can react to. Written target it is. **First task of `/implement`, before any frontend file.**

### D2 — The synthetic fixture must be unmistakable (SPEC §10)
Four independent, redundant signals. Any one surviving is enough:
1. **Banner.** Full-bleed, `position: sticky; top:0; z-index:100`, **not dismissible, no close affordance**.
   Background `--danger` `#de0f80` (Clarity's pink danger — nothing else on the page is pink), text `#fff`,
   13px/600 Inter. Copy: `SYNTHETIC DEMO DATA — these numbers are fabricated. Not a real backtest. Generated <generated_at>.`
2. **`<html data-synthetic="true">`** set from `meta.is_synthetic`. CSS keys off that single attribute:
   banner visible, plus a 3px `--danger` inset border on the page frame. `is_synthetic: false` → attribute
   absent → banner gone, border gone, **zero frontend edits at T5**.
3. **Document title** prefixed `[SYNTHETIC] ` — visible in the browser tab and in any screenshot.
4. **`meta.source: "synthetic_fixture"`** rendered verbatim in the footer's data-source line (see D9).

### D3 — Synthetic *numbers* obviously not-real, without breaking the shape
Shape stays exactly §7; only the values shout. Use **repdigit MAEs** — valid floats, correctly ordered,
instantly readable as fabricated:

- Pure-model MAEs at 6h: `HRRR 5.55`, `NBM 6.66`, `GFS 7.77`, `NAM 8.88` (repdigits, monotonic, plausible units).
- Blend MAEs interpolated on the same repdigit register so the surface is convex and has a real dip
  (the slider and chart must exercise a genuine minimum).
- `join_diagnostics.matched_pct: 88.88`, `mean_abs_offset_min: 8.88`; `n_samples` `{"train": 88, "test": 44}`.
- `meta.site` stays the real KOMA block (the shape and the header must be right), but `meta.site.name`
  is `"Omaha Eppley Airfield (SYNTHETIC FIXTURE)"` so the header itself carries the warning.
- `generated_at` is the real generation time (honest metadata about a dishonest payload).

### D4 — Zero/negative improvement: three explicit states, and the fixture *exercises the negative one*
Threshold ±0.05 pp. Rendering, keyed only on the signed value:

| Value | Tone | Footer copy |
|---|---|---|
| `> +0.05` | `--success` `#37b24d` | `Winner beats the best single model (NBM) by 3.3%.` |
| within ±0.05 | `--text-muted`, neutral | `Best blend ties the best single model (NBM). No improvement — 0.0%.` |
| `< -0.05` | `--danger` `#de0f80` | `No blend beat the best single model. The best blend is 1.2% worse than NBM.` |

Rules: always render the sign; never `Math.abs`; never clamp at zero; the winner row keeps its highlight
but the highlight tone follows the table above — **never green when the number is not positive**.

**Decision that makes this provable:** the fixture emits a **negative** improvement at the 24h lead and
positive at 6h/12h. The dishonest-rendering path is then exercised by the demo itself and by the smoke
check (flip to 24h, assert the danger-toned copy and a leading `−`). Costs nothing; matches SPEC §9's
"the dip may be shallow or absent"; removes the need for a second fixture file.

### D5 — Slider recompute happens **client-side, by exact lookup**, never by arithmetic
Rejected: an API call (same data, extra latency, one more thing to fail at 16:00). Rejected: client-side
recomputation of error (impossible — `results.json` carries no per-sample data, only aggregates).

**Chosen:** the `blends` array *is* the precomputed 0.1-grid. Sliders snap to 0.1 steps; the UI builds the
weight vector and looks up the blend whose `weights` match exactly. **The displayed number is a value read
out of `results.json`, not a number computed in the browser** — agreement is true by construction.

- 4 sliders, one per model, `min=0 max=100 step=10`.
- Renormalization rule when slider A moves to `v`: distribute `1 − v` across the other **enabled** models
  in proportion to their current weights, rounded to 0.1 by **largest-remainder** so the sum is exactly 1.0.
  Deterministic and reproducible.
- Lookup miss (should be impossible): display `—` plus `no grid point for these weights`, and `console.warn`.
  **Never interpolate, never fabricate a value.** This is the §10 "empty join scores perfectly" class.
- Readout element carries `data-weights='{"HRRR":0.7,...}'` and `data-mae-oos="2.02"` so the smoke check
  reads structured values rather than scraping text.

### D6 — Chart: two-model slice, inline SVG, hand-drawn
- Default pair = the two lowest `mae_out_of_sample` pure models (top one from `best_single_model`, second
  from ranking the pure entries in `blends`).
- x = weight of model A, 0→100% in 11 steps; y = `mae_out_of_sample`; other two models held at 0.
  All 11 points exist in the full grid → **exact lookup again, no interpolation**.
- Endpoints dotted and labelled `pure GFS` / `pure HRRR` in their model colors; the slice minimum marked.
- Pair selector: one Clarity `.select` listing the 6 pairs (cheapest; reuses existing token CSS).
- Caption, mandatory: `HRRR vs GFS · NAM and NBM held at 0. The leaderboard above searches the full 4-model weight space; this chart is a 2-model slice.`
- Inline SVG, ~80 lines of JS. **No chart library** — no bundler, and no CDN at demo time.

|---|---|---|---|
| HRRR | `--blue-500` | `#329af0` | BRIEF §8 says HRRR blue — honored |
| GFS | `--orange-500` | `#ff922b` | BRIEF §8 says GFS orange — honored |
| NAM | `--purple-500` | `#a551cf` | data-viz palette |
| NBM | `--green-500` | `#51cf66` | data-viz palette |

### D8 — Backend surface: minimal
| Endpoint | Behavior |
|---|---|
| `GET /health` | `{"status":"ok"}` — kept, but **not** an identity check (squatter answers identically) |
| `GET /api/results` | Whole `results.json` from disk, contract-validated on load. The only data endpoint. |
| `GET /openapi.json` | Free from FastAPI. Title `"Bhar - Site-Tuned Model Blend"` = the identity discriminator |

- **No refetch endpoint.** SPEC §6 says one "may exist but is described, never pressed" — a live-fetch route
  that is never pressed is dead code and a foot-gun on the demo path. The refresh path is *described* in the
  README as the offline CLI (`uv run python -m fetch.backfill && uv run python -m score.run`). If the plan
  wants the surface documented, the only acceptable form is `POST /api/refetch` → **501** naming that CLI command.
- Missing/invalid `data/results.json` → **503 with a specific message**; the frontend shows an empty-state
  card ("No results file. Run the pipeline."). It must **never** serve an empty-but-well-formed object.
- **CORS (TR5):** `CORSMiddleware`, `allow_origin_regex=r"http://(localhost|127\.0\.0\.1):\d+"`. Without it
  the page renders chrome and no data.
- Frontend API base resolution, no build step: `?api=` query param → else `http://localhost:8000`.
  `run.sh` echoes the ready-made URL with the override applied when `BHAR_BACKEND_PORT` is set.

### D9 — `meta.source` gets a third permitted value
§7 shows `"noaa_s3_grib"` / `"open_meteo_previous_runs"` as *examples* of a free string field. The fixture
sets `"synthetic_fixture"`. This is an annotation, not a contract change: the frontend renders the string
verbatim, so T5 changes nothing. It satisfies §10's "the page says which source produced the numbers"
without the fixture ever claiming a real provenance.

### D10 — Vendor Clarity's CSS and fonts now; zero network at 16:00
Probed live at 03:02 — both reachable (`tokens.css` 200, 3685 B; Inter WOFF2 200, 48 432 B).
Download `tokens.css` and the three WOFF2s (Inter / Sora / JetBrains Mono, URLs in the token doc §2.1) into
`frontend/vendor/` and self-host via `@font-face`. Authentic Clarity typography with **no demo-time external
dependency**. Timebox 3 minutes; on any failure fall back to the token font stacks verbatim
(`"Inter", ui-sans-serif, system-ui, …`), which render cleanly on macOS. Not a blocker either way.

### D11 — Light mode only
Clarity's fetchable `tokens.css` is light-only; the demo is a lit room at 16:00; dark values would have to be
hand-copied from the token doc §4. Deferred. Tokens are still authored under `:root` so a `[data-theme=dark]`
block can be dropped in later without restructuring.

### D12 — Fixture kept as a recoverable copy, but no silent fallback
Generator writes **both** `data/results.synthetic.json` (the durable insurance copy) and `data/results.json`
(the served path). If T5's real output fails `validate_results()`, the backend returns 503 and says so — it
does **not** silently fall back to the synthetic file (that would be exactly the fake-green class). The manual
rescue `cp data/results.synthetic.json data/results.json` is documented in the README.

## The T5 seam (swap data, touch no frontend code)
The seam is one file on disk: `data/results.json`, served by `GET /api/results`. T5's obligations, to be
written into T3's deliverables and enforced by the shared validator:

1. Same key set and nesting as §7, exactly.

3. `meta.source` set to the real source string; the page renders it verbatim.

function on the real file. This is what makes the swap provably safe rather than hopefully safe.

## Patterns to Follow
- **Identity, not status code** (T1 retrospective): every verification asserts `/openapi.json` title, never a bare `/health` 200.
- **Refuse rather than degrade** (`run.sh:14-23`): a busy port exits 1 and names the squatter. `/api/results` follows suit — 503 with a reason beats an empty payload.
- Clarity semantic tokens only, never raw scale values (token doc §1.3 rule, verbatim).
- Numbers right-aligned, `--font-mono`, `tabular-nums` (token doc §5.1) — every error value in the leaderboard.
- Toggle idiom = Clarity `.segmented` (token doc §5.3), not custom buttons.
- Slider built from `.progress` geometry (6px track, `999px` radius, `--bg-subtle` / `--accent`) + the 3px `--ring` focus convention (token doc §5.4 — the gap is named there with the primitives to borrow).
- Chart gaps: gridlines `--border`, axis labels `--text-subtle`, tooltip `--bg-elev` + `--shadow-3` (token doc §8.5).

## Patterns to Avoid
- Any client-side arithmetic on error values — lookup only (D5).
- `Math.abs()` or clamping on `improvement_pct_vs_best_single` (D4).
- Hardcoding port 8000 anywhere in the frontend (TR4).
- A chart library, npm, or any CDN reference (TR3, D10).
- Silently substituting the synthetic fixture for a failed real one (D12).
- Hardcoding a leaderboard row count — read it from the data.

## agent-browser smoke check (SPEC §13) — `scripts/smoke_ui.sh`
Outside pytest (it needs running servers; pytest must stay hermetic). Sequence:
1. Assert backend identity: `/openapi.json` title == `Bhar - Site-Tuned Model Blend` (**not** `/health`).
2. Open the page; assert the synthetic banner is present and `<html data-synthetic="true">`.
3. Assert leaderboard renders **N ≥ 9** rows (top 5 blends + 4 pure), N read from the data, not hardcoded.
4. Move a weight slider. Read `data-weights` + `data-mae-oos` off the readout.
5. **Agreement, not change:** independently `curl /api/results`, find the blend whose `weights` match
   `data-weights`, assert its `mae_out_of_sample` equals `data-mae-oos`. Plus assert the value *differs*
   between two distinct slider positions (guards against a static label). Both assertions required.
6. Flip to the 24h lead; assert the negative-improvement copy and a leading minus sign (D4).
7. Assert zero console errors.
8. Screenshot → `.claude/active-work/site-tuned-blend/screenshots/demo-shell.png`.

Any agent-browser malfunction → drop it, note it in the session log, take a manual screenshot. **Never blocks the ticket.**

## Recommended Approach
Contract-first, in strict order: (1) the written design target (D1); (2) `backend/contract.py` validator +
`make_fixture.py` generator with pytest coverage — this locks §7 in code before any consumer exists;
(3) backend `/api/results` with CORS and the 503 path; (4) frontend against the served fixture, all
interactivity client-side by exact lookup into the full 286-point grid. Every honesty requirement (synthetic
banner, negative improvement, exclusions, join diagnostics, source) is driven by data already in the payload,
so T5 swaps one file and changes no frontend code.

## Scope: **L**
Nine new files across two languages plus a design pass and a UI smoke script — the largest surface of the six
tickets. Mitigating: no data logic, no network, no new dependencies, everything deterministic and offline, and
the backend half is roughly 80 lines. Estimate 60–90 minutes. Natural parallel streams for `/plan`:
(A) contract + fixture, (B) backend, (C) design target → frontend, (D) smoke script.
Cut order if the clock bites: pair selector → chart → dark mode (already deferred). The leaderboard,
the banner and the slider are the ticket; nothing else is.
