## Architecture

### Summary

One new module, `backend/forecast_api.py`, holds an `APIRouter` with three read-only GET handlers,
two module-level path constants, four detail-string constants and one shared `_load_forecast()`
helper. It mirrors `/api/results` (`backend/main.py:54-79`) line for line: `.exists()` pre-check →
single `except ContractError` → `HTTPException(503, detail=...)`. `backend/main.py` gains **exactly
two lines** — one import, one `include_router` — and nothing else. Nothing else in the repo changes.

`/api/forecast` and `/api/forecast/skill` share `_load_forecast()` so they can never disagree about
whether the file is servable; `/api/forecast/skill` returns `doc["skill"]` verbatim.
`/api/forecast/history` carries its **real** logic now but resolves the §10 validator **lazily by
name** from the `forecast.contract` module object at request time, so it 503s honestly until F6 adds
one function — and can never serve an unvalidated payload.

## Key Decisions

1. **503 body stays FastAPI's `{"detail": "..."}`.** `/api/results` already returns exactly this;
   F5's fetch handler and F8's curl examples read `detail`. A custom envelope would split the two
   API families for zero gain. *(Research recommendation, adopted.)*
2. **Test seam is the module-level `FORECAST_PATH` / `HISTORY_PATH` constants**, monkeypatched onto
   `tmp_path` — the same indirection `backend.main.RESULTS_PATH` already exposes. **Zero
   configuration surface for F8 to document.** Env vars and `Depends` overrides rejected.
   *(Research recommendation, adopted.)*
3. **History endpoint ships its real logic now, resolving the §10 validator lazily by name.**
   Missing file → 503; file present but no validator → 503 (an unvalidated history payload is never

## Notes for Implementer

- **`data/forecast.json` EXISTS in this worktree** (gitignored, built by F3's refresh). A test that
  forgets to monkeypatch `FORECAST_PATH` will **pass here and fail on a fresh clone**. Task 5.1's
  "all three 503 on an empty tmp dir" test is the mechanical proof that none does.
- **`load_and_validate_forecast` already wraps `OSError` *and* `json.JSONDecodeError` into
  `ContractError`** (`forecast/contract.py:837-852`), and `ContractError` subclasses `ValueError`.
  **One** `except ContractError` covers all four failure modes. Do not add a broad
  `except (OSError, ValueError)` on top — it would swallow real bugs. (`/api/results` has both only
  because `backend/contract.py` is a different, older loader; do not copy that part.)
- **The lazy validator must go through the module object.** `from forecast import contract as
  forecast_contract`, then `getattr(forecast_contract, "load_and_validate_history", None)` at request
  time. A `from ... import` would freeze the lookup and break both the tests and F6.
- **No return annotation on the handlers.** `-> dict` makes FastAPI treat it as a `response_model`
  and run a pydantic pass over the payload. `/api/results` has none; mirror it.
- **Route ordering is a non-issue** — `/api/forecast` and `/api/forecast/skill` are distinct
  literals with no path params. Verified: `/openapi.json` lists both with only `get`.
- **`TestClient` works on the pinned stack** (fastapi 0.141.1 / starlette 1.6.0 / httpx 0.28.1 —
  already in `pyproject.toml`). It emits a `StarletteDeprecationWarning`; pytest's `addopts` is
  `--strict-markers` only, so it is harmless. **Do not add `httpx2`** and do not edit
  `pyproject.toml` / `uv.lock`.
- **POST → 405 needs no code.** FastAPI does it for a GET-only route. Assert it; do not implement it.
- **The fixture is deliberately hostile** — 2 gaps, 7 extrapolated rows, and a real **loss** at 24 h
  (`improvement_pct: -12.5`). Use it; it exercises branches the 64/64-clean live run never does.
- **Build the fixture with pinned aware-UTC instants** and derive `init_time` from
  `forecast.make_fixture.default_init_time(generated_at)` — the builder computes staleness from the
  pair, so a hand-rolled `init_time` can produce a document you did not intend.
- **§9's worked example is defective** — its `blend_f: 78.41` contradicts its own rule 6 (F3 SUMMARY
  §1). F4 never recomputes a blend; do not let `78.41` leak into any expected value.
- **Do not `.get()` around the casing bridge** (F3 SUMMARY §5). F4 does not index models at all —
  keep it that way.
- **Never verify a running service via `/health`.** The port-8000 squatter answers it byte-identically
  and now also serves a "Boreas API" OpenAPI doc. `/openapi.json` → `info.title` is the identity check.
- **A guard that cannot fail is not a guard** (demo team's retrospective, inherited). When Task 4.2
  writes the source scan, feed each pattern a deliberately bad sample and confirm it fires.
- Run everything as `uv run --no-sync ...`. Never `uv pip install`.
