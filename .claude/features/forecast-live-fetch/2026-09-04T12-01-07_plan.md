## 1. Architecture

### Summary

Two new pure-Python modules under a new `forecast/` package. `forecast/cycle.py` is **clock-free
and I/O-free**: it computes the target synoptic cycle from an injected instant, enumerates the
≤4-candidate fallback ladder, and computes age and staleness. `forecast/live.py` is a thin driver
over `fetch.grib.fetch_point` that derives the step grid from recorded probe data, fetches one whole
cycle (Phase A then Phase B) through a `ThreadPoolExecutor(max_workers=8)`, and uses
`data/live/<YYYYMMDDHH>/<model>_f<LLL>.json` as **both the cache and the ledger** — no separate
manifest, so a cache hit is a pure function of what is on disk. `missing` outcomes are cached
alongside `success` ones, which is what makes the zero-network re-run real. Every seam — `fetcher`,
`now`, `cache_root` — is injected, so the whole test suite runs offline.

F2 produces **values**; F3 owns the `forecast.json` contract and the JSON. F2 writes no payload.

### Data flow

```
select_cycle(now_utc, fetcher=, cache_root=)
  │
  ├─ cycle.target_cycle(now_utc)        pure: floor(now − 4 h) to 00/06/12/18z
  ├─ cycle.candidate_cycles(target)     pure: [target, −6 h, −12 h, −18 h]   (4 candidates)
  │
  └─ for each candidate init, in order:
        │
        ├── PHASE A ── fetch_leads(init, [step_grid()[0]])         4 items
        │      any status=="missing"?  ── yes ──> record reason, next candidate
        │                                          (exhausted -> raise NoCycleAvailable)
        │      no
        ├── PHASE B ── fetch_leads(init, step_grid()[1:])         60 items
        │      trailing all-model-complete run  -> horizon_h  (derive_horizon)
        │      interior incomplete step         -> gaps[]
        │
        └── CycleResult(init, target_init, run_label, fetched_at, age_minutes,
                        is_stale, stale_reason, cycles_fallen_back,
                        step_h, horizon_h, grid_max_lead_h, truncated,
                        records{(model,lead)->rec}, gaps[], fallback_reasons[])

fetch_one(model, init, lead, fetcher, cache_root)
  read_cached() ── hit (success|missing, valid JSON) ──> return, NO NETWORK
        │ miss / corrupt / truncated
        └─> fetcher(model, init, lead)            = fetch.grib.fetch_point
              success        -> record status="success", temp_f (degF)
              ArchiveMissing -> record status="missing", temp_f=None, error=<text>
              RuntimeError   -> PROPAGATE. never recorded as missing.
            write_cached()  temp file + os.replace  (atomic)
```

### 2.2 Deriving the grid — the anti-hardcode design

`PROBE_PUBLISHED_LEADS` is the probe's **observation**, written into code as data:

```python
PROBE_INIT = datetime(2026, 9, 4, 12, tzinfo=timezone.utc)
PROBE_PUBLISHED_LEADS: dict[str, tuple[int, ...]] = {
    "hrrr": tuple(range(0, 49)),                               # 49/49
    "gfs":  tuple(range(0, 49)),                               # 49/49
    "nam":  tuple(range(0, 37)) + (39, 42, 45, 48),            # 41/49
    "nbm":  tuple(range(1, 49)),                               # 48/49 — NO f000
}
```

`step_grid()` computes the intersection. **`48` and `3` never appear as loop literals**; they are
the candidate ceiling and step, and the grid that comes out is `(3, 6, …, 48)` *because the data
says so*, not because the spec prose says so. `derive_horizon()` then re-derives the served horizon
from the records actually fetched at runtime, so a short NOAA day truncates and labels rather than
lying (TR6). Tests assert the *properties* of the derivation (every grid lead is published by all
four; no excluded multiple of the step is published by all four), not a copied tuple — a circular
test would prove nothing.

### 2.3 Horizon vs gaps — the precise definitions

- `grid_max_lead_h` = `step_grid()[-1]` — what was **asked for** (48 on a healthy cycle).
- `horizon_h` = the largest grid lead reachable by a **contiguous** all-four-`success` run starting
  at `step_grid()[0]`. Trailing incompleteness truncates it.
- `truncated` = `horizon_h < grid_max_lead_h`.
- `gaps` = grid steps `≤ horizon_h` missing at least one model, each `{lead_h, valid_time,
  missing_models, reason}`.

This keeps §9 contract rule 8 satisfiable (a `valid_time` is in `forecast` **or** `gaps`, never both,
never neither, over the grid **up to `horizon_h`**): truncation removes steps from the universe;
gaps are holes inside it. **Note for F3:** §9's example gap reason reads `"beyond model horizon"`,
which under these definitions describes truncation rather than a gap. F2 emits
`reason="absent from archive"` for interior gaps and hands F3 both `truncated` and
`grid_max_lead_h` so F3 can label the truncation separately. **This is a note, not a contract
change — F3 owns §9.**

### 2.4 Model-name casing (OQ3)

F2 stores and keys **lowercase** (`hrrr`/`gfs`/`nam`/`nbm`), matching `fetch.MODELS` and
`fetch_point`'s return. `results.json meta.models_included` is uppercase. **F3 maps to display
casing when it builds the payload.** F2 must not silently lose the distinction — the plan records
it here and `CycleResult` documents its key casing in its docstring.

### 2.5 The manual live run (FR11)

`forecast/live.py` gets a **minimal `if __name__ == "__main__":` block** (≤ 20 lines, argparse with
exactly `--refetch-missing` and `--cache-root`) so the manual run is `uv run --no-sync python -m
forecast.live` and is reproducible by the next reader. It is not dead code — FR11 presses it, and
its output is pasted into the findings note. **F3's `forecast/refresh.py` is the real CLI and
supersedes it; F2 does not build a scheduler, a payload writer, or any endpoint.**

### 2.6 Cached-`missing` staleness

A cached `missing` freezes a lead NOAA had simply not published yet. Mitigated by the 4 h setback
and the whole-cycle fallback; the escape hatch is `refetch_missing=False` by default — **off by
default is what makes FR8's zero-network property hold.** Do not flip the default.

## 9. Key Decisions

1. **Adopt OQ1's two-phase rule unchanged.** Phase A (f003, 4 requests) decides the fallback ladder;
   Phase B (f006–f048) decides truncation and gaps. It reconciles §5.2 with §5.3, invents no
   numeric threshold, and the probe shows neither branch fires on a healthy cycle. **No dissent.**
2. **Phase A probes `step_grid()[0]`, not the literal `3`.** If the grid's first step ever moves,
   Phase A moves with it.
3. **The grid is computed from `PROBE_PUBLISHED_LEADS` by `step_grid()`**, and the served
   `horizon_h` is re-derived from the records actually fetched. §5.3 is satisfied by a derivation,
   not by a comment claiming one. Tests assert derivation *properties*, never a copied tuple.
4. **The cache directory is the ledger.** Two settled statuses, `success` and `missing`, mirroring
   `fetch/backfill.py:70 SKIP_STATUSES`. No manifest file, so a cache hit is a pure function of
   what is on disk — and caching `missing` is what makes FR8 real.
5. **Only `ArchiveMissing` becomes `missing`; everything else propagates.** Deliberately narrower
   than `backfill.attempt_item`, which maps every failure to a status. Misclassifying an HTTP 500 as
   an archive hole silently deflates coverage and fakes a clean run.
6. **`refetch_missing` defaults to `False`.** Flipping it would break the zero-network property.
7. **A ≤20-line `__main__` in `live.py`** as the FR11 manual-run harness — pressed, not dead code.
   F3's `forecast/refresh.py` supersedes it.
8. **Lowercase model keys throughout `forecast/live.py`** (OQ3); F3 maps to display casing.
9. **`horizon_h` truncates, `gaps` are interior** — the only reading that satisfies §9 rule 8. F3 is
   handed `truncated` and `grid_max_lead_h` so it can label truncation distinctly.
10. **`data/forecast.json` is gitignored by F2 but written by F3** (OQ2) — `.gitignore` gets exactly
    one edit and F2 is the ticket that owns it.

## 10. Notes for Implementer

- **`except ArchiveMissing` must come BEFORE `except RuntimeError`** — `ArchiveMissing` subclasses
  `RuntimeError` (`fetch/grib.py:198`). Reversed, every 404 becomes a hard stop.
- **`fetch/grib.py:_get` wraps `requests.RequestException` in a plain `RuntimeError`** with the
  original as `__cause__`. `except requests.RequestException` in `forecast/` would never fire.
  Documented at `fetch/backfill.py:212`.
- **`_get` already retries once at 120 s.** Do not add a retry layer. A 404 is never retried.
- **`fetch_point` is pure per-call** — no shared session, no global state. Safe to thread-pool as-is.
- **`max_workers=8`. Do not raise it.** GIL-bound decode; spike-F2 validated.
- **NAM emits sub-messages numbered `284.1`.** `int()` on a message number raises — `fetch/idx.py`
  keeps them `str`. Do not "clean this up".
- **NBM CONUS is the `.co` key.** `ak`/`hi`/`pr`/`gu` exist and are wrong for KOMA.
- **`decode_point`'s 0.5° sanity floor is unexercised at f039–f048 for NAM** — a distance failure
  would surface in the manual live run. If it fires, **report it**; do not widen the floor.
- **Naive datetime = UTC, never local** (`fetch/grib.py:54 _as_utc`). Reuse it; do not rewrite it.
- **`datetime.utcnow()` is deprecated and naive.** `datetime.now(timezone.utc)` — and in
  `forecast/cycle.py`, not at all.
- **ISO-8601 with a trailing `Z`** in every cache file (`fetch/backfill.py:90 _iso` house style).
- **Guard messages cite their clause:** `raise ValueError("FORECAST-SPEC §5.2: …")`.
- **An empty result scores perfectly and is fake.** Assert on counts: a `CycleResult` with zero
  records is a failure, not a success.
- **Report what the data says.** If the live run finds a shorter horizon than the probe did, the
  answer is a truncated, labelled horizon — never a tuned experiment (SPEC §10).
