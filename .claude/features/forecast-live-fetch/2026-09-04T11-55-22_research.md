## Cache file layout (recommended, concrete)

```
data/live/
└── 2026090412/                 # <YYYYMMDDHH> of the INIT, UTC. One dir per cycle.
    ├── hrrr_f003.json
    ├── hrrr_f006.json
    ├── ...
    └── nbm_f048.json           # 4 models x 16 leads = 64 files per full cycle
```

One record per file, e.g. `hrrr_f048.json`:

```jsonc
{
  "model": "hrrr",
  "init_time": "2026-09-04T12:00:00Z",
  "lead_h": 48,
  "valid_time": "2026-09-06T12:00:00Z",
  "status": "success",              // "success" | "missing"
  "temp_f": 78.41,
  "grid_lat": 41.3061, "grid_lon": -95.8905, "distance_deg": 0.0043,
  "error": null,
  "fetched_at": "2026-09-04T17:04:12Z"
}
```

**`missing` outcomes MUST be cached too** (`status:"missing"`, `temp_f:null`, `error:"<the
ArchiveMissing text>"`). Otherwise the second run re-requests every 404 and FR8 fails. This
mirrors `fetch/backfill.py`'s ledger, where `success` and `missing` are the two settled statuses
(`fetch/backfill.py:70 SKIP_STATUSES`) — **the cache directory *is* F2's ledger**; no separate
manifest file, so the cache stays a pure function of what is on disk.

## Patterns to Follow

- **Injected seams over monkeypatching.** `fetch/backfill.py:267` takes `fetcher=`, `sleep=`,
  `now=` so no test touches the network or the wall clock. `forecast/live.py` takes the same.
- **Pure time functions.** `fetch/window.py:35 end_init(now_utc)` never reads the clock — the
  whole enumeration is testable at fixed instants. `target_cycle(now_utc)` is its twin.
- **`_iso()` / `_as_utc()` house style** (`fetch/backfill.py:90`, `fetch/grib.py:54`): ISO-8601
  with a trailing `Z`; a naive datetime is UTC, never local.
- **Guard messages cite the clause.** `raise ValueError("FORECAST-SPEC §5.2: …")` — every guard
  in `fetch/` and `score/` names its rule in the message.
- **Real exceptions, never bare `assert`** — `fetch/grib.py` uses `raise AssertionError(...)`.
- **Source-scanning regression tests** for rules a runtime test cannot see:
  `tests/test_grib.py:290-301` greps `decode_point`'s source to forbid the `GRIB_shortName`
  comparison. Copy this technique for "no hardcoded message index in `forecast/`".
- **Settled-status resume rule.** `fetch/backfill.py:195 should_skip` — `success` and `missing`
  are settled; anything else is re-queued. The live cache uses the same two statuses.
- **Atomic write** (temp + rename) as `score/run.py` does; `pathlib`, `pytest` `tmp_path`.

## Patterns to Avoid

- **Re-implementing any part of `fetch/`.** Especially a "simpler" idx parse or decode. §3.
- **"Fixing" `fetch/grib.py` to compare `GRIB_shortName` to `"t2m"`.** See the warning above.
- **Hardcoding a GRIB message index** — NBM's moved 135 → 173 within this very probe.
- **Hardcoding `horizon_h = 48` / `step_h = 3` as literals copied from FORECAST-SPEC.** Derive.
- **Renormalizing weights over a subset of models to fill a gap.** F2 does not touch weights at
  all, and must not add a helper that would let F3 do it. A gap is honest.
- **A parquet cache.** `fetch/schema.py`'s write guard is for the 30-day archive; the live cycle
  is 64 small JSON records that must be readable file-by-file for the cache-hit check.
- **Any broadening of `.gitignore`.** `data/*.json` would untrack `data/results.json` and
  `data/coverage.json`, and would kill `data/forecast_history.json`, which decision-log #14
  requires to be **committed**. Two exact lines.
- **Swallowing every exception into a status**, as `backfill.attempt_item` does. F2's floor is
  narrower and deliberate: only `ArchiveMissing` becomes `missing`; everything else raises.
- **A `datetime.utcnow()` anywhere.** Deprecated and naive. `datetime.now(timezone.utc)`.

## Recommended Approach

Build `forecast/cycle.py` as a **pure, clock-free** module first and unit-test it against a frozen
clock — it is all of the risky *logic* and none of the risky *I/O*. Then `forecast/live.py` as a
thin driver over `fetch.grib.fetch_point`, where **the cache directory is the ledger** (mirroring
`fetch/backfill.py`, minus the parquet/coverage machinery) and every seam — `fetcher`, `now`,
`cache_root` — is injected so the whole suite runs offline. Adopt **OQ1's two-phase rule** to
reconcile §5.2 with §5.3: `f003` for all four decides the fallback, f006–f048 decides truncation
and gaps. Derive `horizon_h` from the records actually fetched, never from a constant. Finish with
one **manual** live run of a real cycle, recorded in the findings note alongside the probe table.

**Why this over the alternatives.** Reusing `backfill.run_backfill` directly was tempting but
wrong: its ledger/coverage/deadline machinery targets 1440 archive items and its `classify` maps
*every* failure to a status, which contradicts F2's "every other non-200 raises". Copying its
*patterns* while keeping the driver small is the right amount of reuse. A parquet cache was
rejected because the cache-hit check must be per-file.

## Scope: M

Two new modules (~150 + ~250 lines), three test files (~30 tests), two `.gitignore` lines, one
manual live run. Comparable to T2 (`grib-point-fetch`, M, landed in one pass). The probe — the
single thing that made this ticket XL-shaped and could have forced a horizon truncation, a NAM
`awip` detour, or an F3 renegotiation — **is already done and came back clean**, which is what
takes this back down to M.
