## Architecture

### Summary

One new Python module, `forecast/scorecard.py`, in three strictly separated layers, because the
acceptance floor is really a purity argument:

**(a) The ledger** — `data/forecast_ledger.jsonl`, committed, append-only. `mode="a"` only, one
complete JSON line per `write()`, flushed, under a module-level `threading.Lock`. Mirrors
`fetch/backfill.py:154-193` line for line. **No code path in this module ever opens the ledger in
a truncating mode**, and a source scan with a positive control proves it.

**(b) The impure passes** — `record()` reads `data/forecast.json` (validated through
`forecast.contract.load_and_validate_forecast`) and appends `(len(models_included) + 1) × len(forecast)`
= **80** prediction rows for a cycle not already in the ledger. `grade()` reads the ledger, offers
only **in-coverage** rows to the *imported* `score.join.join_forecasts_to_obs`, attaches the blend
to its step's observation the way `forecast/history.py:298-320` does, and appends grade rows under a
6 s wall-clock deadline behind exactly **one** bounded `session_get`. Every fetch or join failure
becomes a stated per-row skip, never an exception out of the pass.

**(c) The pure function** — `scorecard(rows, now, *, meta)`. Reads nothing but its arguments. No
network, no disk, no clock. Same ledger in, same JSON out, pinned against committed fixture
ledgers. Both the CLI and the endpoint call it, through the same `serve_scorecard()` composer.

The endpoint is one handler on F4's **existing** router in `backend/forecast_api.py`. The UI is one
new `<section>` in `frontend/forecast.html` plus a **both-sides-bounded region** in
`forecast.js` / `forecast.css`, inserted between F7's END marker and F6's banner.

### Purity boundary (R8, and it is load-bearing)

`recorded_at` / `graded_at` are stamped by the **record/grade** passes, which are impure by nature.
The **pure** function is `scorecard()` alone; a source scan (with a positive control) asserts no
`datetime.now` / `utcnow` / `time.time` / `time.monotonic` / `Path` / `open` / `requests` appears
inside its body. `serve_scorecard()` sits above the boundary and takes `now` as an optional
injected argument.

### Why not the alternatives

A grading daemon is banned and dies silently. A hand-rolled `merge_asof` re-opens the exact bug
`score/join.py:111` documents. A `ThreadPoolExecutor` future to bound the deadline leaves a hung
worker behind, and one HTTP request per pass makes it unnecessary: total wall clock really is
bounded by connect+read. Putting the fetch wrapper in `backend/forecast_api.py` trips a protected
guard at `tests/test_forecast_api_guards.py:349`.

## Key Decisions

1. **Ship the loss.** The blend is beaten by HRRR on the only cycle in the record. §15 and floor #8
   make that the ticket's proof, not its problem. The losing fixture is **real data**.
2. **One cycle, n=12, denominators everywhere.** Adding cycles after seeing an unflattering result
   has the shape of tuning and is indistinguishable from it in hindsight. F8 documents the command
   to grow the record.
3. **The endpoint records as well as grades.** Grade-only would silently lose any cycle where
   nobody ran `--record` — the exact "scheduled job dies quietly" failure lazy grading prevents.
   Recording is pure disk with no network and no deadline exposure.
4. **First-grade-wins on write, latest-wins on read.** A test asserts the committed ledger has no
   duplicate identities, so the two rules can never disagree.
5. **One HTTP request per pass, no thread.** `requests`' `timeout` is per-socket-operation, not
   total; the single-request design is what makes `GRADE_DEADLINE_S = 6.0` honest without a thread
   — and a thread is banned.
6. **The observation window is capped at 7 days.** After long downtime an uncapped window would
   request months of IEM data on a 6 s deadline. Rows beyond the cap stay **pending** with a stated
   reason and a count in `meta.counts`, and the CLI can widen it. Nothing is silently dropped.
7. **`forecast/contract.py` gets no seam.** The scorecard validator lives in `scorecard.py` and
   imports `BANNED_FIELD_NAMES`. One fewer protected file touched.
8. **The F9 frontend region is bounded on both sides**, F7's shape rather than F6's tail-anchored
   one, and is inserted above the F6 banner. F6's extractor slices banner→EOF; appending at the
   tail would put F9 content inside F6's guarded region.
9. **The CLI inventory widens 4→5 deliberately**, with a new positive control proving a sixth still
   fails — F6's precedent. A guard weakened without re-proving it bites is a guard deleted.
10. **The committed ledger grows ~30 KB per cycle** (~120 KB/day at four cycles). Acceptable for
    v1, smaller than the committed 165 KB `forecast_history.json`. **State it in the SUMMARY;
    never compact** — compaction is a rewrite.
