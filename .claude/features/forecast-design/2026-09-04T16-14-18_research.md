## Patterns to Follow

- **T3's `design-target.md` structure, section for section.** Model→colour map stated **once** at §0
  and referenced by name everywhere else; per-region specs naming exact token, size, weight, colour;
  literal CSS blocks confined to the named Clarity gaps; a page-wide numeric-formatting section; a
  cross-cutting notes section carrying load order and viewport.
- **Attribute-gated, unconditional CSS** (`tokens.css:24-46`): markup is always present, visibility is
  a CSS rule keyed on `html[data-synthetic="true"]`, never a JS `display` toggle. Flipping one boolean
  changes everything with zero code edits. **Apply the identical shape to the stale treatment** —
  `html[data-stale="true"]` — so `is_stale` behaves the same way.
- **Sunken-track / raised-pill segmented control** (token doc §5.3) for the back-arrow's day stepper
  and any lead selector — the same idiom `index.html:31` already uses.
- **`.stat-card` for the headline** (token doc §5.6): `.stat-label` 12px muted → `.stat-value` Sora
  30px/600/`-.025em` tabular → `.stat-meta` 11.5px `--text-subtle`. The run label is a natural
  `.stat-meta`, which puts it structurally adjacent to the number and above the fold for free.
- **`.badge-pill` tint/700-text/20 %-alpha-border** (token doc §5.7) for the stale and extrapolated
  markers. `--warn` (`#ff922b`) tone for stale/extrapolated; `--danger` pink is **reserved** for
  synthetic and negative-improvement only (T3 §0's stated reason).
- **Empty state:** icon → title → one sentence → the server's message as `--font-mono` technical
  detail, distinct from the human sentence. **Never apologize** (token doc §5.10, §6 voice rules).
- **Signed values with U+2212**, never `Math.abs`, never clamped (T3 §3).

## Patterns to Avoid

- **Any band, ribbon, shaded envelope, whisker, or `±` around the blend line.** This is the single
  highest-value thing to get right, and it will arrive as a well-intentioned improvement
  (FORECAST-SPEC R5). Model spread, if drawn, is **four discrete member marks or a separate small
  figure** — never geometry attached to the blend value.
- **Re-deriving the model→colour map.** HRRR must be `#329af0` on both pages. Reference `tokens.css`.
- **Inventing a token name.** Clarity has no font-size tokens, no chart tokens, no slider tokens and
  no timeline tokens; sizes are per-component literals. Name the gap, write literal CSS, say so.
- **`--success` green on a non-positive improvement**, and green on anything that merely means "recent".
- **A run label that only appears when something is wrong** — §5.2's explicit anti-pattern; it trains
  the viewer to ignore it.
- **Interpolating across a gap, or renormalizing weights over three models to fill one.**
- **Assuming a 16-cell strip.** The grid comes from F2's probe via `meta.horizon_h`/`step_h`.

## Recommended Approach

**Write the document, do not run the `design` skill.** FORECAST-SPEC §12-F1 offers both forms and
explicitly calls the written `design-target.md` *"the cheaper precedent and it is known to work"*;
decision 15 leaves the choice to the implementer on the clock. The clock is tight — the demo ships at
16:00 and seven tickets follow this one — and the page's layout is **not genuinely uncertain**: T3
already settled the shell, the header, the card system, the model colours, the numeric formatting and
two of the three Clarity gaps, and FORECAST-SPEC §12-F1 enumerates the eight regions. The multi-artboard
canvas buys visual exploration this ticket does not need and costs wall time it cannot spare.

Structure the deliverable as a direct descendant of T3's, so the two documents read as one system:
**§0** reuse notice — model→colour map by reference to `frontend/tokens.css:9-12`, plus the explicit
list of what §6.2 bans in this design; **§1** per-region specs for the eight regions (FR1–FR12), each
naming its tokens, sizes and verbatim copy; **§2** the **one new Clarity gap — the forecast strip** —
with literal CSS, parameterised on `meta.horizon_h`/`step_h`, including the fitted-range boundary, the
band shading and the gap cell; **§3** the stale / extrapolated / synthetic state table, attribute-gated
the way `data-synthetic` already is; **§4** the trust panel's exact past-tense copy, filled with the
real numbers above and with the >24 h no-number statement; **§5** the dark layer (R1) — the
`[data-theme=dark]` block and the pre-hydration script, both scoped to the new files; **§6** numeric
formatting and the back-arrow's signed-error rules; **§7** cross-cutting notes — load order, the
re-author-not-import list (R2), 1440×900, and the run-label-above-the-fold requirement.
