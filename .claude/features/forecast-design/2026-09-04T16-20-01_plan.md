## Architecture

### Summary

F1 produces one markdown document — the written visual target for `frontend/forecast.*` — structured
as a direct descendant of T3's `.claude/features/demo-shell/design-target.md` so the two read as one
system. It specifies eight regions concretely (tokens named, sizes stated, copy verbatim), supplies
literal CSS for the **one** Clarity gap without a precedent (the forward strip), references T3's two
already-shipped gap blocks by path rather than restating them, and carries its own "banned in this
design" block so FORECAST-SPEC §6.2's ban on probabilistic visuals is read before the strip spec that
would most tempt a violation.

Three research findings shape the work and are not optional: `frontend/theme.js` does not exist on
this branch and no `[data-theme=dark]` rule exists anywhere in `frontend/` (so the document must
supply the dark layer itself, scoped to the new `forecast.*` files); `frontend/app.css` is **not** on
§3's permitted-link list (so the document must list the component classes `forecast.css` re-authors
from the token doc — the duplication is correct and is what keeps the demo path byte-identical); and
the 24 h fitted-range boundary lands **mid-strip, between cells 8 and 9**, meaning half the forward
strip is `is_extrapolated_lead: true` and the boundary needs a hard visual break, not a tick mark.

### The BANLIST mechanism (makes the acceptance gate mechanical)

The document must *name* the banned strings in order to ban them, so a naive grep over the whole file
can never pass. The document therefore confines every banned identifier to one delimited block:

```
<!-- BANLIST:START -->
… the §6.2 prohibition, listing every banned field name and the four banned visual forms …
<!-- BANLIST:END -->
```

The gate is: strip that block, then grep. Zero matches outside it. This is the only place the strings
`confidence`, `probability`, `p10`, `p50`, `p90`, `percentile`, `ci_low`, `ci_high`, `error_bar`,
`uncertainty` or the character `±` may appear anywhere in the document — including its prose, its
literal CSS, its class names, and its verbatim copy.

## Key Decisions

1. **Written document, not a canvas.** §12-F1 offers both and calls the written doc "the cheaper
   precedent and it is known to work". The demo ships at 16:00 with seven tickets behind this one,
   and the layout is not genuinely uncertain — T3 already settled the shell, cards, model colours and
   numeric formatting, and §12-F1 enumerates the eight regions. The canvas buys exploration this
   ticket does not need.
2. **Section numbers are the contract, locked in Stream 0.** F5, F6 and F7 are three tickets reading
   one document; stable section numbers are what let each find its own region without reading the
   whole thing. This is the contract-first rule applied to a document instead of a schema.
3. **Parallel drafting into scratch fragments, assembled once.** Four agents editing one markdown
   file would mangle it. Fragments live outside the repo so nothing strays into `git status`.
   Sequential single-agent execution is an explicitly acceptable degradation.
4. **The BANLIST marker block.** A design document that bans a word must print that word. Confining
   every banned string to one delimited block turns "no probabilistic language" from a judgement call
   into a two-line grep that F5 and F7 can re-run against their own source files.
5. **The dark layer is authored here, scoped to `forecast.css`.** §17 says to mirror `theme.js`; it
   does not exist on this branch and no `[data-theme=dark]` rule exists anywhere in `frontend/`.
   Writing the block into the new file keeps `tokens.css` and `vendor/` byte-identical. Light-only
   remains the named fallback if the clock demands, with the block written but unwired.
6. **The re-author-not-import duplication is correct, and the document says so.** `app.css` is not
   linkable under §3. An implementer who finds himself retyping `.card` will otherwise "fix" it by
   linking the off-limits file. Naming the duplication as deliberate is what prevents that.
7. **The boundary gets a hard break, not a tick mark.** Eight of sixteen cells are extrapolated. A
   decorative divider lets a viewer read a 42 h number as measured, which is the precise failure
   §6 exists to prevent.
