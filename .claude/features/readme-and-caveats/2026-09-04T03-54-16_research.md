### The winner-vs-baseline asymmetry — explain it, don't bury it

The baseline (`best_single_model`) is chosen with hindsight: it is the single model with the lowest
**out-of-sample** MAE. The blend is not: its weights are fit on the first 20 days only and then
scored on the last 10. That is deliberately unfair **to the blend**. It is the conservative
direction, and it is the reason a positive `improvement_pct_vs_best_single` means something. A
consequence worth stating: **the winner is not `blends[0]`** — in T3's fixture its out-of-sample
rank was #2 / #5 / **#17**. If T5's real data does the same, the README should not describe the
winner as "the best blend".

### Why the ±30 min join exists (spike F5 / F11, SPEC D8)

METAR is not on the hour — OMA reports at about `:52`. An exact-timestamp join to a model valid
time of `18:00Z` matches **zero rows**, and a zero-row join scores perfectly. The real observation
nearest 2026-08-05 18:00Z is `17:52 = 68.00 °F`, eight minutes early. Hence: nearest valid non-`M`
observation within ±30 min, the signed offset recorded on every row, and a hard raise if matched
rows fall below 80% of expected. The mean absolute offset of **7.92 min** is that `:52` pattern
showing up as data.

### The elevation caveat — what we can honestly say

`data/results.json` cannot carry it (`contract.py` locks `meta`'s keys), so the README is its only
home. **The model grid-cell terrain height was never fetched** — T2/T4 fetch only `:TMP:2 m above
ground:`, never `:HGT:surface:` or an orography field. Do **not** invent a delta in metres.

**Decision (D3 below):** state what is true — station elevation 295.7 m; the nearest grid cell is
used with **no horizontal interpolation and no elevation/lapse-rate correction**; each model's
nearest cell sits at a different place and a different model terrain height, GFS's being the
farthest at 0.119° (~13 km) versus HRRR's 0.012°; a terrain-height mismatch of tens of metres is
a systematic degrees-F offset that shows up in each model's **bias** column and is exactly the kind
of error a v2 bias correction would remove. Quantifying the delta is a named v2 item (one
`:HGT:surface:` fetch per model), not a claim made tonight.
