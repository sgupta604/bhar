## Patterns to follow

- **One boolean, three signals.** `applySynthetic()` (`app.js:57-64`) drives banner + frame + title
  prefix off `meta.is_synthetic` alone. The overview must do exactly the same, not re-derive it.
- **Tokens are the single source of truth for colour**; JS reads them back via `getComputedStyle`
  (`models.js:15-24`, `tokens.css:5-17`). Never introduce a second colour map.
- **Exact lattice lookup, never interpolation** (`models.js:104-118`). Any number the overview quotes
  must be looked up, not computed.
- **`String(lead)` on every index into `results`** — the named trap at `app.js:22-24`.
- **Clarity voice (tokens §6):** "Be useful before being friendly. Direct verbs in titles, sentence
  case in body." No exclamation marks, no emoji, no "Oops!". This is an internal-tools voice, and
  the room is technical.
- **Reuse README prose verbatim where it already says it well** — §1 (headline + GFS caveat), §3
  (what you're looking at), §4 (winner rule), §5.1, §8 (C1/C2/C4/C7). Do not re-invent phrasing;
  the README was reviewed and the wording is deliberately unflattering in places.
- **Load order is load-bearing** (`index.html:7`): vendor tokens → vendor fonts → local tokens →
  layout. `overview.html` must mirror it, with the dark block after the light `:root`.

## Patterns to avoid

- **Do not make `overview.html` the new `index.html`.** `scripts/smoke_ui.sh:20` opens `/` and then
  asserts ≥9 leaderboard rows, exactly one `.is-winner`, and slider behaviour. Repointing `/`
  turns a green smoke check red for a cosmetic reason, 7 hours out.
- **No `prefers-color-scheme`** (tokens §4 forbids it).
- **No brand-mark alteration** — no `filter: invert()`, no single-colour fill, no recolour, no
  rotation (tokens §6b DON'T).
- **No lockup in product chrome** (tokens §6b, verbatim "Never inside product chrome").
- **No hardcoded results in markup** (README §7 / C7 — the window is wall-clock derived).
- **Do not soften the synthetic banner in dark mode.** `--danger` is unchanged in dark by design.
- **No new network dependency**, no icon font, no chart library.

## Decisions (recommended, with rationale — no blocking questions)

**D1 — Serving model: `index.html` stays the product page; `overview.html` is a sibling.**
The frontend is `python -m http.server --directory frontend`; a second page is one more file and
nothing else. Making the overview the index would (a) break `smoke_ui.sh:20`, which opens `/`, and
(b) require moving the product page, which is the one file that must not move today.
`run.sh` and `demo.sh` change **one echo line each**: print the overview URL as `Start here:` and
keep the product URL beneath it. `demo.sh:262-269` should `open` the overview.

**D2 — `?api=` survival: append `location.search` to every cross-page href, at render time.**
Both directions (FR10). One shared helper in `theme.js` (or a 3-line inline script) sets
`a[data-page-link].href = target + location.search`. Rationale: no server, no router, no state; the
query string is the only carrier and it is already the documented contract (`run.sh:65-71`,
README §2). Belt-and-braces: on `overview.html`, if `?api=` is absent, the page still renders prose
(FR8), so a mis-typed URL degrades to "no numbers" rather than "no page".

**D3 — Toggle placement: `.page-header-aside` on the product page, top-right on the overview.**
A `.segmented`-styled two-state control, matching the existing lead-time toggle (`app.css:53-78`)
so no new component vocabulary is introduced.

**D4 — Dark surfaces that need an explicit rule beyond the token swap.** The token swap covers
`body`, `.card`, `.tbl`, `.wbar`, `.slider-*`, `.select`, `.segmented`, `.empty-*`, `.chart-svg`
gridlines/axis and `.chart-tooltip` automatically, because `app.css` is fully tokenized. The
enumerated exceptions:
1. `.improvement-line[data-improvement-state="positive"|"negative"]` (`app.css:342,344`) — uses
   `--success` `#37b24d` / `--danger` `#de0f80`, which do **not** change in dark and read at roughly
   3:1 on `#15181c`. Override to `--green-300` / `--pink-300` per the tokens §4 `.stat-delta` pattern.
2. `tr.is-winner.tone-positive|negative` (`app.css:237,241`) — `--success-soft` / `--danger-soft`
   *are* redefined in dark, so these follow; but verify the `#fff` badge text (`app.css:238,242`)
   still reads on the unchanged `--success`/`--danger` fills. It does.
3. `html { color-scheme: light|dark }` — required, or the native `<input type=checkbox>` model
   chips (`app.css:151`, `accent-color: var(--accent)`) and scrollbars render light-on-dark.
4. `::-webkit-scrollbar-thumb { background: var(--charcoal-700) }` — the verbatim tokens §4 rule.
5. Model series colours → 300 weights (see D5).
6. Synthetic banner + 3px inset frame: **unchanged**, deliberately (SPEC §10).

**D5 — Model colours step to the 300 weights in dark, *and* the colour cache must be invalidated.**
`models.js:14-24` memoizes `_colors` on first call, and `app.js` bakes the resolved hex **inline**
into stacked-bar segments (`:250`), model dots (`:114`, `:295`), slider fills (`:307`) and the chart
series (`chart.js:64,74,88`). Toggling the theme therefore repaints the page background but leaves
every coloured mark on the old palette. Fix: `BharModels.resetColors()` + re-run
`renderModelBar()` / `renderLead()` on toggle. **This is the difference between a dark mode and a
dark mode that "actually works"** — treat it as an acceptance criterion, not a polish item.

**D6 — Brand mark: vendor the PNG, render it at 28 px on a solid light backplate in both themes.**
`s2-mark.png` is two-tone charcoal `#212529` + blue `#329af0`; charcoal on `#15181c` is effectively
invisible. Clarity §6b forbids recolouring or single-colour fill, but explicitly *permits* a solid
backplate ("never place over busy imagery without a solid backplate"). So: a `--r-md` rounded chip,
`#ffffff` or `--charcoal-25`, padding equal to the S-stem height (≈ 6 px at 28 px mark), identical
in both themes. This is compliant, theme-invariant, needs no second asset, and needs no image
editing. Reject `filter: invert()` — it alters brand colour. Same PNG as favicon (TR6).

## Recommended approach

Add `frontend/overview.html` + `overview.js` + `overview.css` as a sibling of the untouched product
page, with `theme.js` and an appended `[data-theme=dark]` block in `tokens.css` shared by both, and
`s2-mark.png` vendored into `frontend/vendor/` and rendered at 28 px on a solid backplate. Bind every
result number on the overview to a live `GET /api/results` read — including the drop-GFS caveat,
which is a real lattice point and needs no hardcoding — and degrade to `—` rather than to a blank
page. The one non-obvious piece of work is that `models.js` memoizes its colour map and `app.js`
bakes hexes inline, so a working dark mode requires a cache reset plus a re-render on toggle, not
just a token block. Ship as one revertible commit; leave `score/`, `fetch/`, `backend/`, `data/` and
every DOM id the smoke check reads entirely alone.

## Scope: M

Three new frontend files, one new vendored asset, an append to `tokens.css`, ~4 dark rules in
`app.css`, small additions to `index.html`, a 2-line change in `models.js`/`app.js`, and one echo
line each in `run.sh` and `demo.sh`. No backend, no data, no contract, no tests to rewrite. The
volume is mostly *writing* — sections 4, 6, 8 and 10 are the ones that carry the demo, and they are
adaptation of existing README prose rather than new thinking. Comfortably inside the window, with a
pre-declared cut order (live numbers → dark mode → brand mark) if it isn't.
