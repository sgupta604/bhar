### Summary

T1 **declares** an environment that already exists. `.venv/` (uv 0.12.9, CPython 3.12.14, cfgrib
decoding real NOAA GRIB2 — spike F12, SPEC §17) is validated and must survive this ticket byte-for-byte

`score/` and `frontend/` ship empty; `backend/main.py` is a ten-line health stub.

## Key Decisions

Research D1–D10 are adopted verbatim. Decisions added at plan time:

- **P1. Stream 4 (`CLAUDE.md`) runs LAST, not first.** The Commands block is `test-agent`'s only
  command source for all six tickets. Writing it after every command has been observed to work means
  it documents reality; writing it first would ship aspirational commands into five later tickets.
- **P2. Task 1.4 is a standalone gated task, not a subtask.** Research R1 (a `uv run` sync mutating
  or recreating the validated `.venv`) is the only failure in T1 that could cost the whole night.
  It gets its own acceptance criteria, its own named escape hatch (`uv run --no-sync`), and its own
  §9 hard-stop branch.
- **P3. `run.sh` is T1's end-to-end verification, not just a file.** The standard end-to-end rule needs
  an owner; `run.sh` starting both services and answering `/health` is the only user-facing behaviour
  T1 introduces, so Task 2.3 verifies it by actually running it.
- **P4. No probe task.** The verification-first rule applies to unconfirmed external interfaces. T1
  touches no external interface — the GRIB path, the venv and the toolchain are all verified in spike
  F9–F12 and SPEC §17. Task 1.4 is a regression guard on that verification, not a new probe.
- **P5. `dev` dependency group rather than a `dev` extra.** Keeps `pytest`/`ruff` out of
  `[project.dependencies]`, so the declared runtime surface is exactly what T2–T5 import.
- **P6. Four tests, not one.** The floor needs one; four cost nothing and each guards a distinct
  assumption (Python version, GRIB stack, `pythonpath`, layout) that a later ticket silently depends on.

- **Timebox: ~20 minutes.** If `uv lock` fights, take `uv run --no-sync`, log it, and move on. T2 is
  the highest-risk ticket and deserves the clock (SPEC §11 R4).
- **Top-level package names `fetch` and `score` shadow nothing** in the dependency set; `pythonpath=["."]`
  puts the repo first. SPEC §6 names these directories — do not rename them to `bhar_fetch` etc.
- **`data/results.json` must stay tracked.** If anything adds it to `.gitignore`, remove that line —
  the backend serves it from disk on the demo path (SPEC §6, research D8).
- **`--strict-markers` is on.** A typo'd `@pytest.mark.intergration` in T2 will error rather than
  silently skip. That is the intent.
- **Do not gold-plate.** Empty packages are correct. A `fetch/idx.py` written "to save T2 time"
  guesses at an interface T2 will discover from a real `.idx`, and guessed contracts are the exact
  failure this pipeline exists to prevent.
